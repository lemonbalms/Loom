## 0. 한 줄 결론

**PreToolUse 비차단 컨텍스트 주입은 이 하네스에서 성립한다(YES).** 훅이 `exit 0` +
`hookSpecificOutput.additionalContext` 를 내면 **도구는 그대로 실행되고**, 그 내용은
**모델 가시 채널에 실제로 도달한다**(요청 본문 실측 · 추측 불가 canary 에코).

**단, 세 제약이 §5.3의 "호출 직전 주입 = 직접 처방"이라는 문장을 지탱하지 않는다:**

| # | 제약 | 결과 |
|---|---|---|
| **C1** | 주입 블록은 **`tool_result` 와 동봉**되어 도착한다 | 그 도구 호출 자체를 교정할 수 없다 — 사후 상기만 가능 |
| **C2** | 스폰된 **서브에이전트 요청에는 도달하지 않는다** | 위임 대상에게 규칙을 실어 보내는 용도 불가 |
| **C3** | 커맨드당 **10,000자 캡이 동일 적용** · 초과 시 `<persisted-output>` 봉투 | 캐시 불가 + 본문 획득에 Read 왕복 부활 (§1.2와 동형) |

부수 실측: 봉투 상태에서 모델이 주입을 **신뢰 불가 채널(프롬프트 인젝션)로 판정하고 지시 준수를
거부**했다 — **2/2 재현**. 수신은 됐다. **수신 ≠ 준수.**

## 1. 실행 좌표

| 항목 | 값 |
|---|---|
| 하네스 | Claude Code **2.1.220** · `bun 1.3.11` · darwin 25.5.0 |
| 프로브 모델 | `claude-sonnet-5` (하네스 능력 측정이므로 세션 모델과 무관) |
| 격리 | 별도 cwd(`probe-cwd`) + 임시 `--settings` — **리포 `.claude/settings.json` 무수정** |
| 지상 진실 | 로깅 프록시(`ANTHROPIC_BASE_URL=127.0.0.1:8788`)가 캡처한 **실제 API 요청 본문** |
| canary | 실행마다 `openssl rand -hex 8` — 프롬프트에 없으므로 에코 = 수신 증명 |
| 증거 아카이브 | `~/.loom/f1-poc-2026-07-26` (payloads 2.7MB · logs · 하네스 일체) |

**영수증·해시가 아니라 수신 실증이다.** 판정 근거는 훅의 exit code가 아니라 캡처된 요청 본문
안에서 주입 블록을 찾은 것이고, 모델 에코는 그 위의 이중 확인이다.

## 2. 프로브와 관측값

| 태그 | 매처 | 주입 자수 | 도구 실행 | canary 에코 | 요청 본문 내 주입 블록 | wall |
|---|---|---:|:---:|:---:|---|---:|
| **p0-control** | (훅 없음) | — | ✓ | **NONE** ✓ | 없음 | 8.75s |
| **p1-inject** | `Bash` | 168 | ✓ | ✓ | `msg[3][1]` **246자** inline | 9.05s |
| **p2-cap9000** | `Bash` | 9,000 | ✓ | ✓ | `msg[3][1]` **9,078자** inline · 말미 마커 보존 | 19.73s |
| **p3-cap10050** | `Bash` | 10,050 | ✓ | ✓ | `msg[3][1]` **2,470자 `<persisted-output>` 봉투** · 말미 마커 소실 | 17.97s |
| **p3b-repeat** | `Bash` | 10,050 | ✓ | ✓ | 동일(재현) | 34.38s |
| **p4-agent** | `Agent` | 168 | ✓ (`PONG`) | ✓ | `msg[3][1]` **247자** inline · **서브에이전트 요청엔 부재** | 19.68s |

통제군 p0가 `CANARY: NONE` 을 낸 것이 측정의 음성 대조다 — canary는 훅이 있을 때만 나타난다.

주입 블록의 실제 형태 (p1 · 요청 본문 축자):

```
msg[3] role=user blocks=['tool_result', 'text']
  block[1] = <system-reminder>
             PreToolUse:Bash hook additional context: [F1-PROBE-BEGIN]
             canary=F1-A69870DDEA3A09F6
             …
             </system-reminder>
```

`Agent` 매처에서는 접두가 `PreToolUse:Agent hook additional context: ` 로 바뀔 뿐 구조는 같다.

## 3. F1 3문항 판정

### ① 도구 실행 지연·차단 여부 → **차단 없음 · 지연 무시 가능**

6개 프로브 전건에서 도구가 실행됐다(`F1_TOOL_RAN_OK` / `PONG`). `permissionDecision` 도
`exit 2` 도 없이 `exit 0` + stdout JSON만으로 성립한다 — **A3(차단)와 다른 경로임이 실증됐다.**

훅 스크립트 자체 런타임 **0.01s(5/5)**. 통제군 대비 wall 차 +0.30s(p0 8.75 → p1 9.05)는
단일 표본이고 훅 기동·주입 토큰 증가가 섞인 값이라 **상한으로만 읽어야 한다.**
p2·p3의 큰 wall 값은 훅 지연이 아니라 응답 길이 차이다(p3b 34s는 모델이 인젝션 경고 문단을
길게 쓴 결과) — **지연 축의 증거로 쓰지 말 것.**

### ② 모델 가시 채널 실도달 → **도달함 (요청 본문 실측)**

`msg[3]` 의 `tool_result` 바로 뒤 `text` 블록으로 들어간다. 추측 불가 canary를 모델이
축자 에코했고, 통제군에서는 나오지 않았다.

**다만 도착 위치가 `tool_result` 동봉이라는 것이 C1의 근거다.** 훅은 도구 실행 **전**에
발화하지만(훅 로그 타임스탬프), 그 산출물이 모델에게 보이는 시점은 **도구 실행 후**다.
그래서 "그 호출을 교정한다"는 쓰임은 성립하지 않는다.

### ③ hook당 10,000자 캡과의 관계 → **SessionStart와 동일 규칙**

- 9,000자 → **inline**(래핑 78자 포함 9,078자), 말미 마커 보존.
- 10,050자 → **`<persisted-output>` 봉투 2,470자**로 치환, 말미 마커 소실.
- 봉투 경로에 **세션 UUID + 도구 호출 ID(`toolu_…`)** 가 박힌다:
  `…/<session-uuid>/tool-results/hook-toolu_01FwL6Hr1LPD2dXvL6SGH6DC-2-additionalContext.txt`

즉 `HOOK-CACHE-FIX-DESIGN` §1.2의 `kou = 1e4` **커맨드당 캡**이 PreToolUse에도 그대로 적용된다.
호출 ID가 매 호출 변하므로 **캡을 넘긴 JIT 주입은 캐시가 절대 히트하지 않고**, 본문을 얻으려면
에이전트가 그 파일을 Read 해야 해서 **P-A가 없애려던 왕복이 부활한다.**

> **Phase 3 예산 규칙**: JIT 주입 1건은 **10,000자 미만**이어야 한다. SessionStart prefix의
> `HARD_CAP 9500` 과 **별도 슬롯**이며 총량 캡은 없다(§1.2 총량 캡 부재 실측과 정합).

## 4. 사전에 묻지 않았는데 나온 것 (Phase 3 설계에 직결)

### 4.1 서브에이전트 미도달 (C2)

`p4-agent` 요청 3건을 분해하면 서브에이전트 요청은 `req013`(툴 88개 · 부모는 91개)이고
**거기에 canary가 없다.** 주입은 **부모 세션에만**, 그것도 서브에이전트가 끝난 뒤 도착한다.

§5.3-2는 JIT의 용도를 "`Agent|Task` 호출 직전에 orchestration 유닛을 주입 → B1(스킬 로드)·
B3(pane 우선)이 요구하던 '기억해서 로드'를 라우터가 대신 수행"으로 적었다. **이 문장은
이번 실측이 지탱하지 않는다** — 위임 시점에 규칙을 실어 보내는 것도, 그 호출을 교정하는 것도
안 된다. 남는 쓰임은 **부모에게 다음 턴부터 적용될 규범을 싸게 얹는 것**이다.

### 4.2 수신 ≠ 준수 (인젝션 판정)

`pad=10050` 두 실행 모두 모델이 주입 내용을 **"도구 출력 = 신뢰할 수 없는 채널에서 온 지시"**
로 명시 판정하고, 지시문 자체는 따르지 않았다고 선언했다(canary는 사용자 지시에 근거해 에코).
`pad=0` · `pad=9000` 에서는 같은 문안이 이 반응을 유발하지 않았다 — **`<persisted-output>`
봉투가 "도구 출력다움"을 키운 것으로 보이나, 봉투와 길이 중 무엇이 방아쇠인지는 이 측정이
가르지 못한다**(교차 설계 미실시).

Phase 3 함의 두 가지:
1. 주입 문안은 **명령형 지시("…하라")가 아니라 규범 진술**이어야 한다 — 명령형은 인젝션
   방어를 때린다.
2. **전달 성공은 준수를 뜻하지 않는다.** Phase 3 게이트("가드가 켜져 있고 잡는다")는
   전달 카나리아가 아니라 **준수 카나리아**여야 한다. F1은 전달만 닫았다.

## 5. 이 측정이 못 가르는 것

- **모델 1종(sonnet-5) · 하네스 1버전(2.1.220) · 매처 2종(Bash·Agent)** 만 봤다. 버전이 바뀌면
  `kou`·블록 배치가 바뀔 수 있다 — `HOOK-CACHE-FIX-DESIGN` §1.2가 정적 분석으로 잡아낸 상수라
  회귀 감시 대상이다.
- **지연은 단일 표본**이다. 규모 있는 주입의 턴당 비용은 Phase 3에서 다시 재야 한다.
- **인젝션 판정의 방아쇠**(봉투 vs 길이 vs 문안)를 가르지 않았다.
- 타 하네스(Codex/Grok)의 PreToolUse 등가물은 **여전히 미확인**(§8-3 그대로 · `NOT_APPLICABLE`).

## 6. 재현 절차

```bash
A=~/.loom/f1-poc-2026-07-26
python3 "$A/proxy.py" 8788 &                     # 로깅 프록시
"$A/run.sh"       p1 "$A/settings-f1.json" 0     # Bash 매처 · 소형
"$A/run.sh"       p3 "$A/settings-f1.json" 10050 # 캡 초과
"$A/run-agent.sh" p4 settings-f1-agent.json 0    # Agent 매처
# 판정: payloads/<tag>__req*.json 에서 "hook additional context" 블록을 찾고
#       canary 포함 여부 · <persisted-output> 유무 · 서브에이전트 요청 부재를 본다
```

`run.sh` 는 매 실행 새 canary를 뽑으므로 **이전 캡처의 canary로는 통과할 수 없다.**
