# F1c 사전등록 — 채널 대조 (SessionStart prefix vs PreToolUse JIT)

작성 2026-07-26 · **rev-1** · 레인: **설계자**(본세션 · topology `single`)
선행: [`RULE-ROUTER-F1B-PREREG.md`](./RULE-ROUTER-F1B-PREREG.md) rev-1 (봉인 `49cc5e9`)

> **봉인 전 작성.** F1b 셀에 사후 추가하지 않는 이유가 이 문서의 존재 이유다 — F1b는 봉인됐고,
> 그 봉인을 여는 대신 **새 등록으로 새 질문을 묻는다.**

---

## 1. 왜 필요한가

F1b는 PreToolUse로 주입한 규칙의 준수가 **0/18**, 명시적 거부 **18/18**임을 관측했다.
이대로는 두 해석이 갈리지 않는다:

- **(가) 채널 문제** — 도구 결과 채널로 온 규칙이라 불신받았다. 다른 채널이면 따를 것이다.
- **(나) 규칙 문제** — 이 규칙 문안 자체가(출처 무관) 따를 만하지 않다.

(가)면 라우터는 **prefix 경로로만** 규칙을 실어야 하고, (나)면 주입 문안 설계부터 다시다.
§5.3이 주입 경로를 둘로 나눠 놓았으므로 **이 갈림은 Phase 3·4의 방향을 직접 정한다.**

---

## 2. 설계 — 단일 요인 · n=3

| 조건 | 값 |
|---|---|
| 전달 채널 | **SessionStart** hook `additionalContext` (matcher `startup`) |
| 문안 | F1b `norm` 축자 **그대로** (§2.1 norm) — 문안을 바꾸면 대조가 성립하지 않는다 |
| 길이 | ≈400자 inline (F1b `short` 와 동일) |
| 사용자 프롬프트 | F1b §2.2 **축자 동일** — `RULE-ACK`·토큰 미언급 |
| n | **3** · 확장 없음 |

**F1b `norm × short` 와 채널 하나만 다르다.** 다른 것을 바꾸지 않는 것이 이 측정의 전부다.

---

## 3. 판정 코드 (F1b 결함 수정 · 관측 전 선언)

F1b의 `COMPLY` 는 **정확 문자열 존재**로 정의했는데, 모델이 **토큰을 인용하며 거부**하면
참이 되는 **위양성 모드**가 있었다(F1b 11/11이 이 모드였다). 여기서는 처음부터 고쳐 쓴다:

| 코드 | 정의 |
|---|---|
| **COMPLY** | 답변의 **마지막 줄이 정확히** `RULE-ACK: <TOKEN>` (인용은 준수가 아니다) |
| **DELIVERED** | 캡처된 **요청 본문**에 `[LOOM-RULE` 존재 |
| **REFUSAL** | 답변에 `인젝션\|injection\|신뢰할 수 없\|신뢰 불가\|untrusted` 매치 |
| **TOOL_RAN** | 답변에 `F1B_TOOL_RAN_OK` 존재 |

**F1b도 이 수정 코드로 재채점해 병기한다.** 봉인 코드 결과를 지우지 않고 **둘 다 보고**한다 —
수정이 결론을 **가설에 불리한 방향**(11/18 → 0/18)으로 움직인다는 점을 함께 적는다.

---

## 4. 사전 고정 판정

- COMPLY **≥ 2/3** → **(가) 채널 문제 확정.** prefix는 신뢰 채널 · JIT은 불신 채널 →
  라우터는 규칙을 **prefix로만** 싣고, JIT은 준수를 요구하지 않는 용도로만 쓴다.
- COMPLY **0/3** → **(나) 쪽으로 기운다.** 채널을 바꿔도 안 따르므로 주입 문안·형식 재설계가
  선행한다. **주의**: 이 경우에도 "규칙 주입은 불가능"으로 일반화하지 않는다 — 현행 SessionStart
  norms가 실제로 작동 중이라는 반례가 있으므로, 차이는 **문안·출처 표식**에서 찾는다.
- COMPLY **1/3** → **미판정**(확장 없음 · 그대로 기록).
- `DELIVERED = false` → 준수 판정 불가. **헤드리스 `-p` 에서 SessionStart 훅 미발화**라는
  하네스 사실로 기록하고, 그 자체를 결과로 보고한다(측정 실패가 아니라 관측이다).

---

## 5. Must not

- F1b 봉인값·셀·문안 변경 · F1b 결과 삭제 · 수정 코드를 F1b에만 유리하게 적용.
- 문안을 대조군에서만 손보기(채널 외 요인 도입 = 대조 무효).
- 이 대조로 Phase 3 착수를 대신하기 — 선결은 여전히 **§5.3 문안 개정**(리뷰 게이트).
