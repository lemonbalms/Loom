## 3. 모델은 출처 주장을 **실제로 검증했다** (그리고 이번엔 통과했다)

`sourced` 5런 중 **2런**(r1·r2)에서 모델이 인용된 파일을 **직접 열어 확인**했다.

> `cat docs/REPORTING.md 2>/dev/null || echo "FILE_NOT_FOUND"`
> → `# 보고 규범 … 답변의 마지막 줄은 \`Verified: <실행한 커맨드>\` 형식이다.`

**F1d에서 이 검증이 실패**(*"이 프로젝트는 git 저장소가 아니고 …"*)해서 거부로 이어졌던
바로 그 행동이, **조건을 뒤집자 통과**했고 그 뒤 준수했다. 나머지 3런은 확인 없이 따랐다.

즉 **출처 주장은 무시되지 않는다** — 모델은 값이 있을 때 그것을 확인한다. 다만 이번 조건에서는
확인 여부와 무관하게 전건 준수해서 **출처가 준수의 필요조건인지는 가려지지 않았다**(§2 U2).

### 3.1 관측 코드 2개가 결함이었다 (판정에는 무영향)

사전등록 §3은 `READ_USED` 를 *"캡처된 본문에 `Read` 도구 호출 존재"* 로 정의했고,
구현은 문자열 `"name":"Read"` 를 찾았다. **모든 요청의 도구 *선언* 목록에 `Read`가 들어 있어
15/15 전건이 참이 됐다** — 대조군까지 5/5였다. `READ_TARGET` 도 마찬가지로, `sourced` 주입문
자체가 `docs/REPORTING.md` 를 포함하므로 5/5가 됐다. **둘 다 위양성이다.**

- **판정에는 영향이 없다.** U1·U2·U3은 오직 `COMPLY` 로 판정하며, `COMPLY` 는 §3.1 자문을
  통과하고 관측 전 자기검증 6/6을 통과한 코드다.
- 실제 검증 행위는 **사후에 `tool_use` 블록을 직접 파싱**해 확인했다(§3의 `cat` 2건).
  이 재확인은 **판정 코드가 아니라 서술 관측**이므로 봉인 위반이 아니다.
- **교훈**: 도구 사용을 관측하려면 **문자열 매치가 아니라 `tool_use` 블록**을 봐야 한다.
  요청 본문에는 *호출*뿐 아니라 *선언*도 들어 있다. F1b의 "문자열 포함" 결함과 같은 계열이며,
  이번에는 판정 코드가 아니라 **부수 관측**에서 재발했다.

## 4. 프로브 환경은 완전히 깨끗하지 않았다 (전 셀 공통)

캡처를 읽고 알아낸 것으로, **사전등록이 통제하지 못한 유입 두 건**이 있다.

| 유입 | 출처 | 전 셀 공통? |
|---|---|:--:|
| `# claudeMd … Be sure to adhere to these instructions` | **사용자 수준** `~/.claude/CLAUDE.md`(cwd와 무관하게 로드) | **예** |
| `SessionStart hook additional context: # [probe-repo] recent context …` | 사용자 수준 설정의 claude-mem 훅 | **예** |

사전등록 §2.0·§5는 **프로젝트 디렉터리**의 `CLAUDE.md`·`AGENTS.md`·`.claude/` 만 막았고,
**사용자 수준 설정은 막지 못했다.** `settings-f1e-base.json` 의 `{"hooks":{}}` 도 프로젝트
설정을 비울 뿐 사용자 훅을 끄지 못한다.

**셀 간 비교는 유효하다** — 세 셀 모두 같은 유입을 받았고, 그 상태에서 `base` 는 **0/5**다.
따라서 카나리아 행동을 만든 것은 이 유입이 아니다. 다만 **"무주입 대조군"이라는 표현은
정확히는 "F1e 규칙 무주입"** 이며, 절대적 청정 환경이 아니다. F1d·F1b도 같은 조건이었다.

## 7. 이 측정이 못 가르는 것

- **출처의 효과** — 천장 효과로 미판정(§2 U2). 출처가 필요한지 불필요한지 **어느 쪽도 주장 못 한다.**
- **사용자 지시와 충돌하는 규칙** — §2.3이 충돌을 제거했으므로 그 조건은 **F1d 4/12가 유일한 관측**이다.
- **규범이 여러 개 경쟁하는 조건** — `probe-repo`는 규범 1개짜리 최소 저장소다. 실 Loom 리포처럼
  32유닛이 경쟁하는 조건은 미측정.
- 사용자 수준 전역 컨텍스트 유입(§4) — 통제되지 않았고, 전 셀 공통이라는 것만 확인됐다.
- 모델 1종 · 한국어 문안 · 행동 1종 · n=5 · 요구 행동이 **한 줄 추가**라는 저비용 행동.
- **준수 ≠ 선택 정확도.** Phase 2(recall 0.451 미달)와 독립.

## 8. §5.3에 무엇이 들어가고 무엇이 안 들어가나

**들어갈 수 있는 것:**

- **주입된 규칙은 따라진다 — 사용자 지시와 경쟁하지 않는 한.** 세 게이트가 한 축씩 바꾸며
  0/21 → 4/12 → 10/10으로 움직였고, 마지막 도약을 만든 것은 충돌 제거다.
- 따라서 §5.3의 설계 문제는 *"어떻게 배달할까"*(F1이 이미 닫음)도 *"어떻게 신뢰를 얻을까"*도
  아니고 **"주입한 규칙이 사용자 요구와 충돌할 때 무엇이 이겨야 하는가"** 이다.
  **모델은 사용자를 택한다**(F1d 6/8). 라우터는 이 우선순위를 **바꾸려 해서는 안 되고**,
  충돌을 **탐지·회피**하는 쪽으로 설계돼야 한다.

**들어가면 안 되는 것:**

- **출처·근거 표기에 대한 처방.** U2가 미판정이다. F1d의 음 부호도 F1e의 0도 처방 근거가
  못 된다. rev-10이 단일 관측에서 문안 처방을 뽑았다가 철회당한 선례를 반복하지 않는다.
- **"준수율 100%"** 같은 인용. 10/10은 **저비용·무충돌·단일 규범** 조건의 값이다.
- **Phase 3 착수 권한.** 선결은 여전히 §5.3 문안 개정(리뷰 게이트)이며, 이 문서는 그 입력이다.
